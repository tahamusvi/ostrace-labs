# Assignment 1

A simple C program is provided Here . Compile the program and run/trace it using strace; Explain all the system calls that are made. Run it for a second time -f flag and see how different the output is.

# compile

```shell
gcc simple_program.c -o program

```

وقتی دستور `strace ./program` رو می‌زنیم تعداد زیادی سیستم کال انجام میشه، اما روند کلی به این صورت هستش که bash یک clone از خودش می‌سازه، سپس کد اجرایی فایل ما لود میشه و بعد از اون اجرا میشه. بخش زیادی از سیستم‌کال‌های اولیه صرف آماده‌سازی محیط اجرا و لود کردن کتابخانه‌های استاندارد (مثل `libc`) می‌شود.

### execve

این سیستم کال دقیقاً میاد کد اجرایی که ما آدرسش رو دادیم جایگزین رفتار کلون bash می‌کنه تا برنامه ما شروع به اجرا شدن کنه.

### brk(NULL)

این سیستم کال میاد آدرس انتهای فضای هیپ (Heap) رو برمی‌گردونه. در ادامه‌ی لاگ هم می‌بینیم که با مقداردهی به `brk`، فضای هیپ برای برنامه بزرگتر می‌شود (تخصیص حافظه داینامیک).

### mmap

این سیستم‌کال برای نگاشت (Mapping) فایل‌ها یا دستگاه‌ها در حافظه پردازش استفاده می‌شود. در این خروجی، `mmap` دو کاربرد اصلی داشته است:
۱. **تخصیص حافظه ناشناس (Anonymous Memory):** برای تخصیص حافظه رم به برنامه (مثل حافظه اولیه).
۲. **لود کردن کتابخانه‌های پویا (Shared Libraries):** نگاشت فایل‌هایی مثل `ld.so.cache` و `libc.so.6` در حافظه تا برنامه بتواند از توابع استاندارد زبان C استفاده کند.

### access / faccessat

این یک چک امنیتی هستش که از کرنل می‌پرسه "آیا فایلی (مثل `/etc/ld.so.preload`) در این آدرس وجود داره و من دسترسی خوندن رو دارم؟" (در این لاگ، فایل `ld.so.preload` وجود نداشته و خطای `ENOENT` برگردانده شده است).

### openat

برای باز کردن فایل‌ها استفاده می‌شود (نسخه امن‌تر و پیشرفته‌تر `open`). در این برنامه برای باز کردن فایل‌های سیستمی (مثل `ld.so.cache` و `libc.so.6`) در زمان راه‌اندازی و همچنین باز کردن فایل `output.txt` جهت نوشتن اطلاعات استفاده شده است.

### fstat

پس از اینکه فایلی باز شد، این سیستم‌کال متادیتا و اطلاعات مربوط به آن فایل (مثل حجم فایل، سطح دسترسی‌ها و نوع فایل) را از کرنل دریافت می‌کند.

### read / pread64

برای خواندن داده‌ها از فایل‌هایی که باز شده‌اند استفاده می‌شود. در این لاگ، `pread64` در حال خواندن هدرهای فایل باینری (ELF) مربوط به کتابخانه `libc` است تا نحوه لود کردن آن را متوجه شود.

### close

فایل دیسکریپتور (File Descriptor) فایلی که قبلاً باز شده بود را می‌بندد تا منابع سیستم آزاد شوند.

### mprotect

برای تنظیم یا تغییر سطح دسترسی یک بخش از حافظه استفاده می‌شود. مثلاً بخشی از حافظه که کدهای کتابخانه در آن لود شده را روی حالت فقط‌خواندنی (`PROT_READ`) قرار می‌دهد تا امنیت برنامه حفظ شود و کدهای اجرایی در طول اجرای برنامه تغییر نکنند (جلوگیری از حملات امنیتی).

### arch_prctl / set_tid_address / set_robust_list / rseq

این مجموعه از سیستم‌کال‌ها توسط کتابخانه C (`glibc`) در زمان راه‌اندازی فراخوانی می‌شوند تا محیط مربوط به مدیریت نخ‌ها (Threads) و Thread-Local Storage (TLS) را برای پردازش تنظیم و آماده کنند.

### prlimit64

برای دریافت یا تعیین محدودیت‌های منابع (Resource Limits) پردازش استفاده می‌شود. در اینجا برای بررسی محدودیت سایز Stack فراخوانی شده است.

### getrandom

یک سیستم‌کال امنیتی است که بایت‌های تصادفی را از هسته لینوکس دریافت می‌کند. معمولاً `libc` از این اعداد تصادفی برای تولید Stack Canary (برای جلوگیری از حملات Buffer Overflow) یا مقادیر امنیتی دیگر در زمان لود برنامه استفاده می‌کند.

### write

این سیستم‌کال داده‌ها را در یک فایل یا خروجی می‌نویسد. در این برنامه دو بار استفاده شده است:

1. نوشتن رشته `"Hello World!\n"` درون فایل `output.txt` (روی فایل دیسکریپتور شماره 3).
2. چاپ کردن متن `(This is the Parent process (PID: ...` روی خروجی استاندارد ترمینال (روی فایل دیسکریپتور شماره 1 که همان `stdout` است).

### clone

معادل مدرن سیستم‌کال `fork` در لینوکس است. این سیستم‌کال یک پردازش فرزند (Child Process) جدید ایجاد می‌کند. در لاگ می‌بینیم که `clone` فراخوانی شده و خروجی آن ایجاد فرزندی با `PID: 239176` بوده است.

### getpid

شناسه پردازش (Process ID) فعلی را از کرنل دریافت می‌کند تا بتواند آن را در خروجی ترمینال چاپ کند.

### SIGCHLD / exit_group

* **SIGCHLD**: یک سیگنال است (نه سیستم‌کال) که نشان می‌دهد پردازش فرزند کارش تمام شده و خارج شده است (`CLD_EXITED`).
* **exit_group**: سیستم‌کالی است که به اجرای پردازش فعلی و تمام نخ‌های (Threads) وابسته به آن پایان می‌دهد. کد `0` نشان‌دهنده خروج موفقیت‌آمیز برنامه است.
