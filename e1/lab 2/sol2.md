تو مرحله قبل فهمیدیم برنامه فقط داره با رم کار میکنه و حافظه میگیره و پس میده

حالا میخوام ببینم که جز کد اصلی برنامه هستش یا مثلا کتابخونه ها دارن اینکارارو میکنند.

برای این کار از یک تکنیک به نام Call Graph Profiling (ردیابی گراف فراخوانی‌ها) استفاده می‌کنیم.

با این دستور ما ریکورد رو اماده میکنیم:

```shell
sudo perf record -e 'syscalls:sys_enter_mmap,syscalls:sys_exit_mmap' --call-graph fp ./lab2
```

با این دستور دیتا رو میبینیم

```shell
sudo perf script
```

ما تو این دیتاها کلا دوتا فاز داریم
فاز ld-linux (لودر) و فاز libc (کتابخانه C).

_start: این نقطه ورودِ (Entry Point) واقعیِ باینریِ شماست. وقتی کرنل فایل lab2 را اجرا می‌کند، پرش می‌کند به این آدرس.

__libc_start_main: محیط اجرای زبان C بالا می‌آید. این تابع آرگومان‌ها (argc, argv) را تنظیم کرده و سیستم را برای کدهای شما آماده می‌کند.

main+0x3b: این همان تابعی است که شما در فایل سورس‌کد خود نوشته‌اید. برنامه‌ی شما بالاخره اجرا شده و در حال انجام محاسبات خود است. عبارت +0x3b نشان می‌دهد که ما کجای تابع main هستیم (احتمالاً چند خط بعد از شروعِ بدنه تابع).

__mmap+0x2c: در داخل تابع main، شما صریحاً درخواست تخصیص حافظه داده‌اید. برنامه‌ی شما تابع mmap را صدا زده که در کتابخانه‌ی استاندارد C (libc) قرار دارد.

syscalls:sys_enter_mmap: این خط نشان می‌دهد که کتابخانه libc درخواست شما را بسته‌بندی کرده و سیستم‌کال را اجرا کرده است. اینجا دقیقاً لحظه‌ای است که دیوارِ بین User Space و Kernel Space شکسته می‌شود و کنترل به هسته‌ی لینوکس واگذار می‌گردد. کرنل باید 0x00001000 بایت (دقیقاً ۴ کیلوبایت یا یک Page کامل) حافظه تخصیص دهد.
